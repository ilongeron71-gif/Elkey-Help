# Elkey: Help

Единый Telegram-бот для нескольких групп на Cloudflare Workers + D1.
Проект использует JavaScript ES Modules и Telegram Bot API без сторонних runtime-библиотек.

## Что входит

- Ранги 0–4, отдельные для каждой группы; ранг 4 зарезервирован за `OWNER_ID`.
- Модерация: бан, мут, кик, предупреждения и настраиваемое наказание за лимит варнов.
- Антифлуд: лимит сообщений в окне времени и обнаружение трёх одинаковых сообщений подряд; настраиваемое действие.
- Правила, приветствия с `%u`.
- Архив Telegram-файлов по `file_id` (документы, фото, видео, аудио, voice, animation, video note).
- Контакты/триггеры с точным совпадением текста.
- Пользовательские RP-команды с `%u` и `%t`, плюс восемь базовых RP-команд.
- Дуэль на три раунда: игроки соревнуются, кто первым нажмёт кнопку; статистика считает завершённые дуэли.
- Созывы с кликабельными упоминаниями; `.Анрег` исключает пользователя, `.рег` возвращает.
- Профили и недельная статистика.
- Ручная чистка и опциональный автобан участников ниже недельной нормы.
- Личные обращения через `/communication`, очередь обращений и ответ администрации.

Каждая группа имеет свои настройки, ранги, архив, контакты и RP-команды. Пользовательская запись и ID общие между чатами. Поле баланса хранится в профиле, но правила начисления/перевода валюты не заданы и экономические команды не включены — их нельзя считать готовой экономикой.

## Требования

- Node.js 20+.
- npm.
- Аккаунт Cloudflare с Workers и D1.
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).

## 1. Установка и D1

```bash
npm install
npx wrangler login
npx wrangler d1 create elkey_help
```

Команда D1 вернёт `database_id`. Вставьте его вместо `REPLACE_WITH_D1_DATABASE_ID` в `wrangler.toml`. Для этого комплекта рекомендуется отдельная новая D1-база: схема отличается от раннего неполного прототипа из переписки и не является миграцией поверх его вручную созданных таблиц.

Примените миграции к удалённой базе:

```bash
npm run db:migrate:remote
```

Для локальной базы:

```bash
npm run db:migrate:local
```

## 2. Секреты

Задайте секреты через Wrangler:

```bash
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
npx wrangler secret put OWNER_ID
npx wrangler secret put SUPPORT_IDS
```

- `BOT_TOKEN` — токен от BotFather.
- `WEBHOOK_SECRET` — случайная строка из латинских букв, цифр, `_` и `-`, длиной 32–64 символа. Например, сгенерировать можно командой `openssl rand -hex 32`.
- `OWNER_ID` — числовой Telegram ID владельца. Только этот ID получает ранг 4.
- `SUPPORT_IDS` — ID администраторов поддержки через запятую, например `11111111,22222222`. Для работы `/communication` обязательно укажите хотя бы один ID.

Не помещайте реальные токены в `wrangler.toml`, исходный код, Git или публичные сообщения.

## 3. Права бота в Telegram

Добавьте бота в каждую группу администратором. Выдайте только необходимые права:

- **Ban users / Restrict members** — бан, кик, мут и автонаказания.
- **Delete messages** — удаление сообщений при антифлуде.
- Администраторский статус также нужен для достоверного `getChatMember` и получения `chat_member` updates.

Для `.мут` используйте супергруппу: Telegram Bot API документирует `restrictChatMember` именно для супергрупп. Обычную группу при необходимости преобразуйте в супергруппу.

Бот-администратор получает сообщения группы, необходимые для статистики и антифлуда. Если убрать у бота администраторский статус, для получения обычных сообщений придётся отключить Privacy Mode через BotFather (`/setprivacy`), но тогда команды модерации всё равно не смогут работать без нужных админ-прав.

## 4. Публикация Worker

```bash
npm run check
npm run deploy
```

После публикации Cloudflare покажет URL вида:

```text
https://elkey-help.<your-subdomain>.workers.dev
```

Webhook endpoint — `/telegram`.

## 5. Подключение Telegram Webhook

В терминале задайте переменные окружения `BOT_TOKEN` и `WEBHOOK_SECRET` (те же значения, что добавлены в Cloudflare Secrets), затем выполните:

```bash
curl -sS "https://api.telegram.org/bot${BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=https://elkey-help.<your-subdomain>.workers.dev/telegram" \
  --data-urlencode "secret_token=${WEBHOOK_SECRET}" \
  --data-urlencode 'allowed_updates=["message","callback_query","chat_member"]'
```

Проверьте результат:

```bash
curl -sS "https://api.telegram.org/bot${BOT_TOKEN}/getWebhookInfo"
```

В ответе `url` должен указывать на Worker, а `last_error_message` не должен содержать ошибок доставки.

Webhook защищён заголовком `X-Telegram-Bot-Api-Secret-Token`. Повторные `update_id` дедуплицируются в D1.

## 6. Локальная разработка

```bash
cp .dev.vars.example .dev.vars
# Заполните локальные значения в .dev.vars
npm run db:migrate:local
npm run dev
```

Локальный Worker не получит Telegram updates сам по себе: для теста webhook нужен доступный HTTPS URL (например, временный туннель) и переключение `setWebhook` на этот URL. Не оставляйте production webhook на локальном адресе.

## Команды

Все команды группы начинаются с точки. Регистр букв не важен. Команды модерации выполняются **ответом на сообщение пользователя**.

### Модерация

| Команда | Действие |
|---|---|
| `.варн причина` | Выдать предупреждение |
| `.мут 10 причина` | Мут на 10 минут; если время не указано — 10 минут |
| `.бан причина` | Постоянный бан |
| `.кик причина` | Удалить из группы с возможностью вернуться |
| `.ранг 1` | Назначить ранг ответившему пользователю |

Ранги приложения независимы от администраторских прав Telegram: Telegram-администратор не получает автоматически ранг Elkey. При этом реальные Telegram-администраторы защищены от наказаний через Elkey.

Ранги:
- `0` — участник;
- `1` — модератор: варн, мут, кик;
- `2` — администратор: также бан и настройки;
- `3` — доверенный администратор: может назначать ранги до 2, включать авточистку и созывать;
- `4` — владелец, только `OWNER_ID`.

Назначать ранг 4 нельзя. Нельзя модерировать самого себя, владельца, Telegram-администраторов и пользователей с равным или более высоким рангом. Перед действием бот проверяет Telegram-статус цели.

### Правила, приветствия и антифлуд

| Команда | Пример |
|---|---|
| `.УПравЧ текст` | Установить правила |
| `.УПривЧ Добро пожаловать, %u!` | Установить приветствие |
| `.правила` | Показать правила |
| `.лимитварнов 3` | Наказание после 3 варнов |
| `.наказаниеварнов mute` | `mute`, `ban` или `kick` |
| `.мутварнов 60` | Длительность авто-мутa за варны, минуты |
| `.антифлудлимит 6` | Количество сообщений в окне |
| `.антифлудокно 5` | Размер окна, секунды |
| `.антифлуд warn` | Действие: `warn`, `mute`, `ban`, `kick`, `delete` |
| `.мутфлуда 5` | Длительность авто-мутa за флуд, минуты |
| `.антифлуд off` | Отключить антифлуд |
| `.антифлудлимит 6` | Вернуть рабочий лимит после отключения |

По умолчанию антифлуд срабатывает при 6 сообщениях за 5 секунд или при 3 одинаковых сообщениях в окне. Модераторы ранга 1+ исключены. Для удаления сообщений боту нужно право `can_delete_messages`.

### Архив файлов

Команды `.УАрхФ имя` и `.ОАрхФ имя` нужно отправлять **ответом на сообщение с файлом**.

- `.УАрхФ правила` — добавить файл.
- `.ОАрхФ правила` — заменить существующий файл.
- `.ВАрхФ правила` — отправить файл из архива.
- `.САрхФ` — показать список.

Архив сохраняет Telegram `file_id` и тип файла. Файлы не скачиваются в Worker и не копируются в D1/R2. Тип файла при повторной отправке сохраняется: фото отправляется как фото, документ как документ и т.д. `file_id` принадлежит конкретному боту и не переносится на другого бота.

### Контакты и триггеры

Формат использует разделитель `|`:

- `.УСЧ помощь | Напишите модератору @name` — добавить триггер.
- `.ОСЧ помощь | Новый ответ` — изменить ответ.
- `.ССЧ` — список.
- `.ВСЧ помощь` — показать сохранённый ответ.
- `.ДСЧ помощь` — удалить.

Если обычное сообщение в группе полностью совпадает с именем триггера без учёта регистра, бот отправляет его значение.

### RP-команды

Создание: `.СРК 😘 | 😘 %u чмокнул %t 😳`

Вызов: отправьте `😘` ответом на сообщение цели. Можно использовать и dot-триггер, например `.СРК .чмок | 😘 %u чмокнул %t 😳`, затем вызвать `.чмок`.

- `%u` — имя автора действия.
- `%t` — имя цели.
- `.РК` — список.
- `.УдалРК .чмок` — удалить пользовательскую команду.

Встроенные: `.обнять`, `.чмок`, `.пнуть`, `.погладить`, `.датьпять`, `.укусить`, `.похвалить`, `.пожатьруку`.

### Дуэлянты и созывы

- `.дуэль` — ответом на сообщение соперника; 3 раунда, каждый раунд выигрывает первый нажавший кнопку.
- `.Анрег` — не участвовать в созывах.
- `.рег` — снова участвовать.
- `.созыв текст` — созвать известных боту активных участников (ранг 1+; до 150 упоминаний за одно сообщение).

Незавершённая дуэль автоматически считается устаревшей через час при следующем запуске игры или при ежедневном Cron-обслуживании.

### Профили, статистика и чистка

- `.профиль` — свой профиль; ответом на сообщение — профиль участника. В сообщении профиля есть вкладки «Обзор», «Игры» и «Баланс».
- `.стата` — свой профиль и статистика.
- `.стата чат` — статистика чата за 7 дней.
- `.журнал [N]` — последние 1–20 действий модерации (ранг 2+).
- `.норма 20` — минимум 20 сообщений за скользящие 7 дней; `0` отключает норму.
- `.чистка` — показать кандидатов ниже нормы.
- `.чистка подтвердить` — вручную обработать до 8 кандидатов за запуск.
- `.авточистка вкл` — включить автоматическую проверку (ранг 3+).
- `.авточистка выкл` — отключить.

Cron запускается ежедневно в 00:00 UTC и проверяет скользящее 7-дневное окно. Для соблюдения лимитов Free-плана один запуск обрабатывает не более 7 кандидатов и проверяет максимум 8 групп; между группами действует ротация по времени последней проверки, поэтому одна крупная группа не должна постоянно вытеснять остальные. Telegram-администраторы, владельцы и участники с приложным рангом выше 0 не банятся.

В статистику попадают только сообщения, полученные ботом после установки. Существующий список всех участников Telegram Bot API не предоставляет; участник попадает в базу после первого сообщения или update о вступлении, пока бот уже добавлен и подписан на `chat_member`.

### Личная связь

В личном чате с ботом:

- `/communication` — включить режим обращения;
- отправить следующее сообщение или вложение — создать обращение;
- `/cancel` — отменить ввод.

Администраторы поддержки (из `SUPPORT_IDS`) получают копию обращения. Каждый ID из `SUPPORT_IDS` должен хотя бы один раз открыть бота и отправить `/start`, иначе Telegram не позволит боту первым написать этому администратору. В личном чате с ботом поддержки доступны `/tickets` и `/reply ID текст`.

## Архитектура и ограничения

- **Workers** — webhook и обработка команд.
- **D1** — долговременные данные, отдельные настройки каждой группы и игровые состояния.
- **Cron Trigger** — ежедневная проверка недельной активности и очистка старых логов.
- **KV не используется**: для текущего набора функций состояния уже надёжно хранятся в D1, отдельный кэш только усложнил бы согласованность.
- Архив хранит `file_id`, а не бинарные файлы. Если потребуется собственное долговременное файловое хранилище, можно добавить R2.
- D1 обрабатывает запросы одной базы последовательно. Лимит хранилища — 500 MB на Free и до 10 GB на Paid; D1 Free допускает до 50 запросов на один Worker-вызов. `batch()` считается одним запросом и используется для объединения связанных операций. Для очень крупных сетей групп стоит перейти на несколько D1 баз/шардирование и очереди.
- На Workers Free ориентиры: 100 000 входящих запросов в сутки, 10 ms CPU на HTTP/Cron-вызов, до 50 subrequests на вызов и до 5 Cron Triggers на аккаунт. У D1 Free — 500 MB на базу и до 50 D1-запросов на Worker-вызов; `batch()` помогает объединять statements. Фактические тарифные лимиты могут меняться — проверьте актуальную страницу Cloudflare перед ростом нагрузки.

## Проверка перед запуском

1. `npm run check` проходит без синтаксических ошибок.
2. SQL-миграции выполняются в SQLite/D1.
3. `BOT_TOKEN`, `WEBHOOK_SECRET`, `OWNER_ID` заданы.
4. `SUPPORT_IDS` содержит хотя бы одного администратора поддержки.
5. Бот назначен администратором с `can_restrict_members` и `can_delete_messages`.
6. Webhook показывает правильный URL и `allowed_updates`.
7. Проверены команды в отдельной тестовой супергруппе, а не в основном сообществе.

Этот проект — готовая исходная база для развёртывания, но реальные действия Telegram (бан/мут/удаление, получение обновлений и отправка файлов) нельзя проверить без вашего токена, прав бота и тестовой группы.
